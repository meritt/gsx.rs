# AGENTS.md

The `gsx/1` markup language and its projections: one Rust core behind thin bindings for npm (Wasm), SwiftPM (XCFramework) and PyPI (ctypes). Design: [docs/architecture.md](docs/architecture.md); reasoning: [docs/decisions/](docs/decisions/readme.md).

## Rules

- Format rules live only in `gsx-core`. Bindings translate types and errors and add no logic of their own.
- Core modules depend only downward along the chain in [docs/architecture.md](docs/architecture.md#pipeline).
- A target's declaration and its rendering come from one table; never describe behaviour separately from the code that runs it.
- Public offsets are UTF-16 code units of the input.
- Tests cover library behaviour and performance only; the corpus in `testdata/` is the acceptance test.
- No comments in code beyond the `SAFETY:` notes and `# Safety` sections clippy requires; constraints go to `docs/`.
- Everything in the repository is in English. Commit messages: one line, capitalised.

## Layout

| Path | Contents |
|---|---|
| `crates/gsx-core` | parser, document, serializer, measurement, projections; no I/O, no `unsafe` |
| `crates/gsx-ffi` | C ABI; `include/gsx.h` is generated by cbindgen |
| `crates/gsx-wasm` | wasm-bindgen exports for `@meritt/gsx-wasm` |
| `xtask` | build, corpus, replay, release set, benches |
| `packages/npm`, `packages/swift`, `packages/python` | bindings; the Swift manifest is `Package.swift` at the root |
| `schema/` | JSON Schema of the wire format |
| `testdata/corpus` | golden corpus, written by `cargo xtask corpus`; never edited by hand |
| `testdata/bench` | bench cases and baselines |
| `tools/` | Unicode table and test-file generators, bench report summary |
| `fuzz/` | `cargo-fuzz` targets, outside the workspace |

## Setup

Toolchains are pinned by `rust-toolchain.toml`, `.nvmrc` and `packages/npm/package.json` (`devEngines`). Remove Homebrew `rust`: it shadows rustup.

```bash
cargo install wasm-bindgen-cli --version "$(cargo pkgid -p wasm-bindgen | cut -d@ -f2)" --locked
brew install binaryen
rustup toolchain install nightly-2026-11-01 --profile minimal --component miri,rust-src
```

`wasm-opt` must report version 133.

## Corpus

```bash
cargo xtask corpus
```

Regenerates every expected result in `testdata/corpus` from gsx. `cargo test` compares them exactly; after a change in behaviour, run `corpus`, review `git diff testdata` and commit the diff with the change, and record the rule a new case pins in `docs/decisions/`. The fixtures in `crates/gsx-core/tests/project/` are frozen and not regenerated.

| File | Case |
|---|---|
| `syntax.jsonl` | input → tokens, marker ranges |
| `document.jsonl` | input → document |
| `diagnostics.jsonl` | invalid input → codes, ranges |
| `editor.jsonl` | incomplete input → ranges, diagnostics |
| `targets/<target>.jsonl` | input and facts → fields, measurements, changes |

Inputs are CommonMark 0.31.2 and GFM spec examples, publication scenarios, generated constructs, inputs at budget and target limits, and known defects of other parsers; each case lists them in `sources`. Properties cover panics, range validity, serializer idempotence, fitting within limits and determinism.

## Replay

```bash
cargo xtask replay
cargo xtask replay python
```

`replay` builds every package, installs each as a consumer (pnpm, SwiftPM, a venv of `python3` or `GSX_PYTHON`) and compares its parse, serialize and projection JSON for the corpus with Rust byte for byte; `replay python` (or `npm`, `swift`) does one, which is all Linux can run. It also enforces the `gsx.wasm` gzip budget.

## Benches

```bash
cargo xtask bench
cargo xtask bench --wasm
cargo bench -p gsx-core --bench instructions
cargo +nightly-2026-11-01 fuzz run parse -- -max_len=4096
```

`bench` writes `testdata/bench/baseline/gsx-<commit>.json` and its `.md` summary; `--wasm` builds the npm package and writes `gsx-wasm-<commit>` in Node.js. CI compares Callgrind instruction counts with the base commit and fails a case more than 1% above it; wall time on shared runners is too noisy. Instruction counts need Valgrind and `gungraun-runner` of the `gungraun` version in `Cargo.lock`. Fuzzing needs `cargo install cargo-fuzz`; the targets are `parse` and `project`.

## Build

```bash
cargo xtask header
cargo xtask wasm
cargo xtask xcframework
cargo xtask wheel
cargo xtask dist [<empty dir>] [--wheels <dir>]
cargo xtask pin [--check] [<release set>]
```

`dist` builds the release set, replays each package as a consumer, and adds the Linux wheels CI built in their PyPA images (`--wheels`); `pin` points `Package.swift` at the set's XCFramework.

## Release

1. Set `version` in `Cargo.toml` (`[workspace.package]`), `packages/npm/package.json` and `packages/python/pyproject.toml`; merge to `main`.
2. Take the release set CI built for that commit and pin it:

   ```bash
   gh run download <run-id> --repo meritt/gsx.rs --name release-set --dir /tmp/gsx-set
   ```

   ```bash
   cargo xtask pin /tmp/gsx-set
   ```

3. Merge the pin to `main`, tag it and push the tag:

   ```bash
   git tag -a vX.Y.Z -m "vX.Y.Z"
   ```

   ```bash
   git push origin vX.Y.Z
   ```

4. Once the Release workflow is green, publish the released artifacts and the tagged crate:

   ```bash
   gh release download vX.Y.Z --repo meritt/gsx.rs --pattern 'gsx-*' --dir /tmp/gsx-release
   ```

   ```bash
   pnpm publish /tmp/gsx-release/gsx-vX.Y.Z-npm.tgz --access public
   ```

   ```bash
   uv publish /tmp/gsx-release/gsx-X.Y.Z-py3-none-*.whl
   ```

   ```bash
   git checkout vX.Y.Z && cargo publish -p gsx-core --locked
   ```

Repository settings: immutable releases enabled.

Recovery:

| Failed at | Action |
|---|---|
| Identity, Gates, Build | rerun; for a code fix delete the tag (`git push origin :refs/tags/vX.Y.Z`), fix on `main`, tag again |
| Draft, Readback, Publish | `gh release delete vX.Y.Z --repo meritt/gsx.rs --yes`, rerun |
| Immutability | rerun the failed job |
| Published release is wrong | release the next patch version |
